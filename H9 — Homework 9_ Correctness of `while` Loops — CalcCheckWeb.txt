[3]

We reason about while loops using the following inference rule:
Primitive inference rule “While”:
`B ∧ Q ⇒⁅ C ⁆ Q`
⊦—————————————————————————————————————
`Q ⇒⁅ while B do C od ⁆ ¬ B ∧ Q`

Notice how the subproof for “While” establishes the premise of the “While” rule, and how the calculation step with calculation operator ⇒⁅
while B do C od ⁆ uses the conclusion of the “While” rule as one step in the whole calculation.

For the variables of the “While” rule, note that B and C are parts of the program that is subject to the proof.
The invariant Q however needs to be provided


ideally as part of the program development process;
in any case at the time of proof.
That means: If the program developer did not document the intended invariant, you have to invent an appropriate invariant yourself.
The invariant will need to hold
immediately before the loop starts,
after each execution of the loop body,
and therefore also after the loop ends.
In general, invariant generation cannot be automated. (But there is a flourishing research area investigating automatic invariant generation in
special cases.)
In practice, an appropriate invariant often can be obtained by generalising the loop postcondition, keeping in mind that the invariant will typically
mention all variables that are changed by the loop, and will explain how they are related.
